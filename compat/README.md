# Differential testing against the Go reference implementation

This directory runs the library side by side with
[transparency-dev/merkle](https://github.com/transparency-dev/merkle)
v0.0.2 — the Go implementation behind Trillian, Rekor and the
Certificate Transparency tooling — and requires the two to agree.

`./compat/run.sh` builds both sides, has the Go side write a corpus, and
replays it against this library. It runs in CI on every push and pull
request (the `differential` job), so a change that makes this library
disagree with the reference fails the build.

## What is compared

The Go side builds one log (1500 leaves by default: the empty leaf,
`leaf-<i>` strings, and random bytes of random length) and writes:

| line | content | this library must |
|---|---|---|
| `R` | the root of every prefix of the log | compute the same root (`Log.root_at`) |
| `P` | inclusion proofs: every `(index, size)` up to size 64, plus random draws from the whole log | produce the same hashes in the same order (`Log.inclusion_proof`) |
| `Q` | consistency proofs: every `(old, new)` up to size 64, plus random draws | produce the same hashes in the same order (`Log.consistency_proof`) |
| `I` | calls to `proof.VerifyInclusion`, with Go's verdict | return the same verdict (`verify_inclusion`) |
| `C` | calls to `proof.VerifyConsistency`, with Go's verdict | return the same verdict (`verify_consistency`) |

Agreeing on honest proofs is the easy half. The `I` and `C` lines are
mostly dishonest: each honest query is followed by about two dozen
damaged copies — index and sizes off by one or two, doubled, halved,
zeroed, swapped, or pushed out by 2<sup>40</sup>; the proof truncated at
either end, extended at either end (with a random hash, with the root,
with the old root), reversed, with its ends swapped, or with one bit
flipped; a leaf or a root with one bit flipped. Some of those are still
valid — the audit path of leaf 0 has the same shape in a tree of three
leaves as in a tree of four — which is exactly why the verdict is taken
from the reference rather than assumed. With the default settings that is
about 128 000 verdicts.

## The one documented difference

For `old_size = 0` the Go verifier accepts any `root1`. This library also
requires it to be the root of the empty tree, `H("")`, as the `.mli`
says: a caller holding some other "root of size 0" is holding something
that is not a tree head. `replay` counts these queries separately and
does not treat them as failures. Any other disagreement is one.

## Running it

```sh
opam exec -- ./compat/run.sh
```

Needs `dune` and `go` (1.21 or later). The Go module and its checksums
are pinned in `go/go.mod` and `go/go.sum`. Output goes to
`compat/_out/` (ignored by git; the corpus is about 85 MB).

| variable | default | meaning |
|---|---|---|
| `SEED` | `20260917` | seed for leaf data and for the damage applied to proofs |
| `LEAVES` | `1500` | size of the log |
| `EXHAUSTIVE` | `64` | every proof is compared up to this tree size |
| `QUERIED` | `40` | every verification query is generated up to this tree size |
| `SAMPLES` | `1500` | random draws from the whole log, each compared and queried |

## The checked-in vectors

`test/reference_vectors.ml` — roots, audit paths and consistency proofs
of a 1000-leaf log, used by the ordinary test suite so that it needs
neither Go nor a network — is generated by the same program:

```sh
(cd compat/go && go run . vectors) > test/reference_vectors.ml
```

`run.sh` fails if that file is not what the reference currently
produces.
